**Proposed:**

- **Tiger Data depth**, in this order:
  1. A `reports` hypertable on `reported_at`.
  2. Expiry as a SQL filter using a time limit per hazard kind.
  3. A continuous aggregate of hazards per segment per hour, so the app can say "icy 3 of the last 5 mornings".
  4. Retention and compression policies.

## Working rules

- Use one short-lived branch per item above, cut from a fresh `main` (`git pull` first). Merge back as soon as tests pass. Pull `main` into long-running branches every few hours.
- Keep frontend and backend in their own folders so the two tracks rarely conflict.
- Never describe a route as "safe" in UI copy or API text, and never imply Accessible mode is guaranteed accessible. See the mode descriptions in `routing.py`.
- Keep confirmed reports, unverified reports and AI predictions separate in storage and in the UI. That's a requirement from the brief.
- Secrets go in `backend/.env`, which git ignores. Never commit them.
